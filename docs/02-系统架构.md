## 2.2 分层与职责边界

全局作用域共享。**依赖单向向下，下层绝对不能调用上层。** `data` 与 `engine` 平级，互不依赖。

```
config → store → data ─┐
                        ├→ ui → interact → main
              engine ──┘
```

| 层              | 核心职责                                                     | 绝对禁止                                                 |
| --------------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| **config.js**   | 业务常量、无副作用纯工具函数（`isZZ500Product`）             | 副作用函数、业务数字散落到其他文件                       |
| **store.js**    | 内存变量、localStorage 读写、Observer 广播、快照导入、配置版本号 | DOM 操作、网络请求、业务计算                             |
| **data.js**     | 取数（网关 / `DATA_MODE:"direct"` 下的腾讯直连 / 采集器 KV 读端点）、TTL 缓存、`fetchSingleFund`、`getNavByCode`、云端读写 | DOM 操作、业务计算、localStorage 读写、在既定取数分支**之外**新加 fetch（D-013 起直连本身不再禁止，见 4.3 纪律 #10） |
| **engine.js**   | 纯函数：市场状态、PE 取值（`getAnchorPE`/`getRefPE`，数值来自旁路引擎百分位，**插值机制已不存在**，见 D-016）、权益计算、增降权推演、今日盈亏、基准代理回填。**依赖全部参数传入** | DOM、localStorage、调用 store/data 函数                  |
| **ui.js**       | DOM 读写、格式化、卡片/表格渲染、`UI_update*` 订阅响应 | 业务计算、localStorage 读写                              |
| **ui-holding.js** | 持仓抽屉与增降权预案的 `UI_*` HTML 工厂（只返回字符串，DOM 写入交给 interact） | 业务计算、localStorage 读写 |
| **ui-pe.js**    | 指数栏 `renderIndices`、PE bar `updatePeBar`、`UI_updateIndices` 订阅响应 | 业务计算、localStorage 读写 |
| **interact.js** | 响应用户事件，协调 store/engine/ui，显式调用 `syncCloud`     | 核心数学公式（委托 engine）、直接操作 localStorage       |
| **main.js**     | 初始化、定时器、Observer 订阅绑定                            | HTML 拼接、业务逻辑、直接 DOM 操作（事件绑定除外）       |

**config.js 纯工具函数**：函数体内只做字符串/数值运算，不读写外部状态。当前收录 `isZZ500Product(name)`。engine 调用它不违反依赖注入。

## 2.3 Observer 数据驱动

写入 store → store 广播 → 订阅者自动响应。**调用方不需要、也不应该手动调渲染函数。**

| 频道           | 触发时机                            | UI 响应                  |
| -------------- | ----------------------------------- | ------------------------ |
| `FUNDS`        | 净值刷新、列表增删                  | `UI_updateFunds()`       |
| `INDICES`      | 指数行情刷新（10 秒）               | `UI_updateIndices()`     |
| `LOCAL_CONFIG` | PE 定锚、持仓/降权预案/优先卖出变更 | `UI_updateLocalConfig()` |

- **云推送不挂广播**：`syncCloud` 由 interact 在配置变更时显式调用。`FUNDS` 同时被每分钟净值刷新触发，挂订阅会产生无意义 API 调用。正确调用点：`addFund`、`delFund`、`saveHoldings`、`confirmPe`，各自显式调用 `syncCloud("push_pe_now" / "push_config")`。
- **配置版本号不广播**：`bumpConfigVer()` 仅写 localStorage 作同步判据，不渲染、不挂频道。

## 2.4 运行时数据流

**主刷新（60 秒）**

```
main setInterval(60s) → refreshData(force=false)
    → fetchIndices()              // 网关 /v1/indices ｜ 直连：腾讯单源（D-020）
    → fetchOfficialData(funds, force) // 读 KV /v1/nav/today → officialBatchCache（D-025 TTL 策略）
    → fetchSingleFund() × N       // 纯合并，无网络请求；官方条目携带 previousNav/previousDate
    → error 条目 → LKG 回退        // direct：getLastResults() → offSource:"stale"（D-025）
    → applyProxyEstimates()       // 入库前回填代理估值（D-022）
    → setLastResults()            // → 广播 FUNDS → UI_updateFunds()
    → Sortable 销毁重建

main setInterval(10s) → fetchIndices() → setIndices() → 广播 INDICES
    → UI_updateIndices()          // 指数条 + PE 栏
    → reapplyProxyEstimates()     // 代理重算 → setLastResults → 广播 FUNDS（D-022）
                                  // 权益% / 持仓总额 / 最新收益 / 估算列因此 10 秒一动
```

> **三组数据体系**：
> ① 实时指数 ② 官方净值窗口（`nav:previous` + `nav:today`）③ 业绩基准代理（计算自 ① + 产品库 + 官方基准净值）
>
> **官方净值：唯一来源是采集器 KV**（D-023 G 节）。
> `fetchOfficialData` 只读 `NAV_BASE/v1/nav/today`，**不看 `DATA_MODE`**；拿不到就走
> `officialBatchCache` 上次好数据。**不许再加"直连兜底"**——浏览器侧东财恒被 `ErrCode:61136`
> 拦、腾讯只有一路，兜不出第二个源。前端已删 `_fetchEastmoneyOfficial` / `EM_BASE`，
> `_parseTencentFunds` 也不再产出 official 块。
> 刷新按钮 `refreshData(true)` 绕过两层缓存实时请求（D-025）；`fetchSingleFund` 返回 error 时
> 从 `getLastResults()` 取上次好数据标 `offSource:"stale"`（direct 模式 LKG 回退，补齐红线 #2）。
>
> **数据源双模只管盘中数据（估算、指数）**（D-013）：`DATA_MODE` 切两条链路——
> - `"gateway"`：走网关端点，主备 + KV last-known-good 在网关内。
> - `"direct"`：浏览器直连。盘中行情单次请求取 6 个顶部可见指数和 4 个隐藏估算因子；**指数单源腾讯**——
>   新浪备源因不返回 CORS 头在浏览器侧取不到，代码已于 D-020 删除，
>   **本文档任何地方都不得再写"指数有主备"**（此处曾长期写着"备新浪"，D-023 时修正）。
>   返回格式：腾讯 GBK（`TextDecoder("gbk")` 解码）。
>   字段产物与网关逐字段对齐，下游 `fetchSingleFund` / `setIndices` / `setQQIndex` 无感。
>
> **官方净值夜间采集器**（D-023）：`workers/fund-nav-collector/`，
> 带 Cron 的 Worker，9:00–24:00 每分钟一跳（cron 已由 D-027 更新），`Promise.allSettled`
> 并行打东财与腾讯，逐只只收 `officialAt === 今日` 的净值，**先到先得**（`src` / `at` 写入后不可变），
> 两源都给出当日数据时按**完成时间**选先到的，平局归东财（D-026，取代 D-023 A 节"东财平局胜"）。
> 写 `nav:previous` 与 `nav:today` 两个窗口 key，同时保留 `nav:{date}` / `nav:latest` 作迁移兼容。
> `nav:today` 表示“最新已公布的官方净值日”，不是北京日历当天；新官方净值真正采到后才滚动。
> 存在理由是两条**浏览器侧无解**的约束：
> 东财前端直连被 `ErrCode:61136` 拦（仅服务端调得通），且无人开着看板时浏览器根本不会去取。
> ⚠️ **读写分在两个部署里**：Worker 只写；读端点 `/v1/nav/today` 挂在**网关** `router.mjs`
> （Worker 拿不到大陆可达域名），故 `NAV_BASE = API_BASE`。读端点**先 today 后 latest**——
> 盘中 / 周末 / 节假日没有当日记录，不回退就整列变空。返回的 `date` 是记录自带日期，
> 两类口径（红线 #6）据它照旧判新旧。因此官方列**可能混源**，见 `03-实现约束.md`。

> **真实估算链已删除**：
> 前端不再请求 `/v1/funds/estimate` 或腾讯 `jj{code}` 的估算块，也不再读写估算 localStorage / `fm_est.json`。
> “盘中估算”列保留，但其内容是基准代理净值；收益金额只读净值差，不读估算百分比反推。
> 隐藏估算因子只进入现有行情 Map，不参与顶部展示，也不是官方净值。
> 当前 4 个隐藏因子固定为：南方A500ETF `159352`、企债指数 `000013`、
> 科创50 `000688`、创业板指 `399006`。direct 与 gateway 都把它们并入原有单次行情请求，
> 不增加第三条取数路径。

**指数实时（10 秒）**

## 2.5 云同步与配置版本机制

**三个云端文件**

```
fm_pe.json     ← p 字段，PE 定锚（高频；无版本号，内容比对）
fm_config.json ← v / f / h / s / pr（低频；v 为版本时间戳，置 JSON 首位）
fm_log.json    ← 操作日志（用户可随意清空，不影响同步）
```

**拉取流程**

```
syncCloud("pull")
    → cloudFetchPe() + cloudFetchConfig()        // 两文件并行
    → 两文件均拉取失败 → return false             // 唯一的「真失败」
    → importPeSnapshot()                          // PE 内容比对，相同跳过
    → importSnapshot()                            // config 版本比对：remoteV > localV 才采纳
    → 本地 v 仍比云端新 → setTimeout 反向 push_config 自愈
    → refreshData()                               // 拉取成功即刷新（无论有无变更）
    → return true
```

**配置版本 `v`**：本地时间字符串 `YYYY-MM-DD HH:mm:ss`，置于 JSON 首位（可肉眼读最后修改时间），按字典序即时间序。

- **自增**：配置内容变更（`saveFunds` / `saveHoldingsData` / `savePrioritySell` / `clearPrioritySell`）时，store 封装函数内置 `bumpConfigVer()` **同步**落地——不放在防抖推送里，确保推送被杀也不丢版本。
- **采纳**：`importSnapshot` 仅在 `remoteV > localV` 时采纳云端并把本地 v 抬到 remoteV，否则跳过。**幂等由此保证**，同一份配置不重复导入。
- **反向自愈**：拉取后若本地 v 仍更新，延迟触发 `push_config` 推回云端，他端下次打开即收敛，永不回退。
- **PE 不版本化**：每日单端录入、即时推送、`importPeSnapshot` 读 localStorage 本就幂等，无需版本化。

**pull 返回值语义**：表示「拉取是否成功」，非「内容是否变更」。仅两文件都取不到才 `false`；取到任一即刷新并 `true`（即使无变更）。`manualPull`/`openCloudConfig` 据此判定成败提示，`main.js` 据此决定是否本地补刷。

## 2.6 市场数据网关（workers/）

> **本节写「前端必须遵守什么」。** 业务上的"为什么"在 [`01-业务意图.md`](01-业务意图.md)；

>
> ⚠️ **操作性规则必须留在这里**——2026-07-20 的事故正是因为「拿不到新数据就用旧的」
> 这条规则只活在代码里、没进正文（见 D-001）。
> 该规则的业务理由现已固化在 `01` §1.1「陈旧可以接受，陈旧且不告知不行」。

⚠️ **本节以下描述的是 `DATA_MODE === "gateway"` 这条链路。** 原文曾写「浏览器只请求 `API_BASE`
下的三个端点，不再直连任何第三方域名」——那是 D-008 时代的无条件表述，**已被 D-013 / D-023 推翻**，
现行取数路径见 §2.4 与 4.3 纪律 #10。JSONP 机制确已整体删除，这一条仍然成立。

当前实际取数格局（`DATA_MODE` 实际值为 `"direct"`）：

```
官方净值（唯一来源，不受 DATA_MODE 影响，D-023 G 节）
  fund-nav-collector（Worker+Cron）── 写 ──> KV ── 读 ──> 网关 /v1/nav/today ──> 浏览器

实时指数走 DATA_MODE 双模：
  "gateway"  浏览器 ──→ fund-api.bailuzun.com ──→ /v1/indices 主:腾讯 备:东财 push2delay
  "direct"   浏览器 ──→ qt.gtimg.cn（指数单源腾讯，GBK 须 TextDecoder）
```

> `/v1/funds/official` 已随 D-023 G 节退役（`EM_BASE` 与前端直连官方的两条取数函数一并删除），
> 官方净值改由上面那条采集器链路供给。

`"gateway"` 模式下主备选择、整组完整性校验、GBK 解码全部在 Cloudflare Pages Functions 内完成
（`workers/fund-market-api/`，部署步骤与接口契约见该目录 README）。以下规则适用于该模式。

- **前端不判主备**：只消费网关返回的 `status`（`primary`/`backup`/`stale`/`unavailable`）。
- **`stale` = 网关的 last-known-good 回退**：两条线路都取不到时网关返回上次那份完整好数据，
  `ok` 仍为 `true`、原始时间戳原样保留。
  **前端必须渲染它并明确标记陈旧**——指数走 `mode:"stale"`（`idx-bar` 显示「行情暂断 · 显示 HH:MM 数据」），
  基金卡片与表格走 `srcTag()` 的「陈旧」两个小字。**静默沿用是这套设计唯一不接受的结果。**
  KV 回退的取舍与事故经过见 D-001，网关侧字段与降级行为见 `workers/fund-market-api/README.md`。
- **整组成败**：任一组请求失败或 `ok:false`，整组降级为不可用，**禁止把半组数据交给渲染层**。
  ⚠️ **"这次请求不可用" ≠ "把已有数据清空"**。不可用时走网关的陈旧回退（`status:"stale"`），
  绝不把用户已看到的数据冲成空。这条边界见 D-001 与
  D-002——2026-07-20 的事故正是把本句误读成了"许可清空"。
- **指数核心组与隐藏因子分开判定**：6 个可见指数必须完整；4 个隐藏估算因子缺失时只跳过对应因子，核心行情组仍可用。隐藏因子不新增顶部单元格。腾讯代码依次为 `sz159352`、`sh000013`、`sh000688`、`sz399006`；东财 secid 依次为 `0.159352`、`1.000013`、`1.000688`、`0.399006`。
- **in-flight 请求去重**：同一 cacheKey 的并发请求只打一次上游，纯网关内部行为，前端无感。
  实现与理由见 D-011。
- **指数组主线路是腾讯，不是东方财富**：PE bar 锚定 `getAnchorPE`，默认解析到 `getEnginePE1`（1.0 总市值路，见 D-017），唯一输入是沪深300
  实时总市值，而东财唯一可达镜像 `push2delay` 只给点位（`f115=f116=0`）。网关据此要求主线路必须带
  HS300 的 `pe`/`marketCap`，缺失即整组切备用。
- **备用指数源仍要写 `setQQIndex`**：备用只是缺总市值，点位是有的。2.0（点位路）照常可算，1.0 由
  `getEnginePE1` 自己的 `mcap>0` 判据回落昨收——**不要在 data 层用 `mcap>0` 一刀切掉两路**。
- **2.0 的显示不挂 `isDynamic`**（那取自 1.0）：走备用时 1.0 失效、主数字冻回昨收，此刻点位路的 2.0
  是仅存的实时估计，正该露出来。
- **所有上游子请求都带缓存击穿参数**：部分上游前面挂第三方 CDN，曾按出口 IP 把响应缓存住 40+ 分钟不更新；`upstreams.mjs` 的 `fetchWithTimeout` 统一给每次上游请求 URL 追加时间戳参数并传 `cf.cacheTtl:0`，不影响 `router.mjs` 的短 TTL 节流缓存。
- **盘中代理整套降级**：主模型所有行情腿齐全时才计算；任一腿缺失则整套切到 `fallbackLegs`，两套都不完整返回空值，禁止半套混算。

**主线路不出声**：页面寸土寸金，主线路是常态，不占任何版面。只有降级到 `backup` 才提示，且各自就近
显示，不新增行、不新增区块：

| 数据组 | 备用时的提示 |
| --- | --- |
| 指数 | `idx-bar` 既有的 `data-status` 窄行（9px）显示「备用行情」 |
| 估算 / 官方 | 卡片内各挂两个小字（`srcTag()` → `.src-tag`） |
| PE | 2.0 百分位数字**正下方**挂同样两个小字，代表 1.0 锚失效、bar 已退回昨收 |

官方组的 `offSource`（D-023 D 节起，**允许逐只混源**）：值优先取采集器逐只记下的 `navSource`

## 2.8 夜间 PE 数据引擎（automation/，独立于前端看板）

**定位：旁路锚的数据源，不是看板 PE 定锚。** 它写的是 `fm_pe_engine.json`，与 2.5 节 `fm_pe.json`
（你每晚手录的定锚）是**完全不同的 Gist 文件**，AI 不要混为一谈。

```
automation/pe_nightly.py（GitHub Actions 跑，非本地）
    └─ 夜间：抓乐咕沪深300滚动PE
        → 写 Gist fm_pe_engine.json（js/interact.js 的 pullPeEngine() 拉取，30分钟节流、失败静默）
```

**前端只消费 5 个字段**：`date` / `peYest` / `priceYest` / `mcapYest` / `peSorted`。
`mcapYest` 是 1.0 总市值路的锚，`priceYest` 是 2.0 点位路的锚，`peSorted` 供百分位二分查找。
payload 里的 `pctYest`/`peQQYest`/`priceQQYest`/`n` 前端不读，是抓取副产品，留着便于肉眼看 Gist。

- **触发方式**：`.github/workflows/pe-night-engine.yml` 不用 cron，由外部 Cloudflare Worker
  （Master-Scheduler）通过 `repository_dispatch`（`night`/`sentinel` 两种 type）唤醒；
  `night`→`RUN_SLOT=early`（乐咕没更新则温和退出等下一槽），`sentinel`→`late`（仍没有则报错）。
  `workflow_dispatch` 仅作手动/手机兜底入口。本工作流**只写 Gist、不回提交仓库文件**（`contents: read`）。
- **`workers/pe-night-trigger/src/index.js`**（2026-07-20 前路径：`automation/cf_worker_pe_trigger.js`）：Worker 侧触发器。密钥全走 `env.*` 绑定，代码不含明文（沿革见 4.5）。
- **排班本身不归本仓库管**：几点唤醒、唤醒哪个 action，全在中控 `Master-Scheduler` 里，那是**独立的私有仓库**
  （`srbaby/Master-Scheduler`，本地 `D:\Projects\Master-Scheduler`），账户级基础设施，同时服务本项目与 X-Plan。
  本仓库只管收到 `repository_dispatch` 之后做什么。**要改时间点就去那个仓库改并重新部署，别在这里找。**

### 双路验证层已拆除（2026-07-19）

原有 16:00 快照 + 夜间与官方配对 + `validation-log.json` 的整套比对，其唯一目的是回答「1.0 和 2.0 哪个准」。
15 个可比对交易日（06-25 ～ 07-17）的结论已经足够确定：

| | 1.0 总市值路 | 2.0 点位路 |
| --- | --- | --- |
| 平均绝对误差 | 0.41pp | 1.31pp |
| 最大绝对误差 | 0.86pp | 3.69pp |
| 误差 >1pp 天数 | 0 / 15 | 6 / 15 |
| 逐日更接近官方 | 14 / 15 | 1 / 15 |

故 `pe-snapshot.json`、`validation-log.json`、`RUN_ACTION=snapshot` 分支、Worker 的 `snapshot` 路由
一并删除，Master-Scheduler 侧 16:00 那一跳应同步取消。**2.0 保留在看板上**：成分调整日总市值会跳变，
那种日子点位路反而是有效参照。若日后要重建验证，从 git 历史取回即可，不要在引擎里留半套。
