```text

├─ fund-nav-collector：官方净值双源采集并写 NAV KV
└─ pe-night-trigger：触发 GitHub Actions 夜间 PE 任务

GitHub Actions
├─ pe-night-engine.yml：运行 automation/pe_nightly.py，写 fm_pe_engine.json

├─ fm_pe.json：用户 PE 档位配置
├─ fm_config.json：带版本的基金、持仓和预案配置
├─ fm_pe_engine.json：自动生成的夜间 PE 锚与历史序列
```

## 2.2 前端分层

加载顺序必须保持：

```text
config → store → data → engine → ui → ui-pe → ui-holding → logger → interact → main
```

| 层 | 负责 | 不负责 |
|---|---|---|
| `config.js` | 业务参数、代码映射、时间与模式开关、纯工具 | DOM、请求、存储 |
| `store.js` | 内存状态、localStorage、安全读写、Observer 广播 | 外部请求、业务计算、DOM |
| `data.js` | 盘中行情、官方净值 KV、Gist 读写、缓存与解析 | DOM、业务决策、直接写 localStorage |
| `engine.js` | PE、权益、收益、增降权和代理计算的纯函数 | DOM、存储、外部请求 |
| `ui*.js` | HTML 与界面渲染 | 写 store、云同步 |
| `logger.js` | 同步诊断日志 | 业务状态 |
| `interact.js` | 用户操作、调度 store/data/engine、显式云同步 | 复制底层算法 |
| `main.js` | 启动、定时器、Observer 接线 | 业务参数和算法 |

`ui-pe.js` 有一项经批准的只读计算例外，边界见第三篇 §3.6；不得扩大到写状态或触发同步。

## 2.3 Observer 数据流

Store 只广播变化，渲染方订阅对应频道：

| 频道 | 典型来源 | 订阅行为 |
|---|---|---|
| `INDICES` | `setIndices()`、`setIndicesUnavailable()` | 重画顶部指数，并重算代理 |
| `FUNDS` | `setLastResults()`、基金列表变化 | 重画基金、收益和持仓相关视图 |
| `LOCAL_CONFIG` | PE 档位、持仓/预案变化 | 重画本地配置区域 |

指数到货必须触发 `reapplyProxyEstimates()`。它会更新基金结果并广播 `FUNDS`，从而让代理净值、
权益、总资产和收益一起随 10 秒行情刷新；漏接这条线会让页面卡到下一轮 60 秒净值刷新。

## 2.4 数据源登记表

这是项目当前数据源及其职责的唯一总表。

| 数据 | 正式来源 | 备份/降级 | 传输与缓存 | 前端用途 |
|---|---|---|---|---|
| 官方基金净值 | 采集器并行请求东财 `FundMNFInfo` 与腾讯 `jj` 官方块 | 逐只采用先返回的当日官方值；不是整组主备 | `fund-nav-collector → NAV KV → /v1/nav/today`；前端批量缓存及逐只 LKG | 市值基准、相邻净值日收益、代理基准 |
| 盘中指数/ETF行情 | 腾讯 `qt.gtimg.cn` | `gateway` 模式下东财三镜像为整组备源；`direct` 模式没有第二浏览器源 | direct：浏览器单次请求；gateway：`/v1/indices` + `MARKET_LKG`；本地另存指数快照 | 顶部 6 指数、PE 外推、4 个隐藏代理因子 |
| 基金盘中代理 | 前端 `BENCHMARK_PROXY` + 当前行情因子 | 主模型缺一腿则整套切 `fallbackLegs`；两套都不完整返回空 | 本地纯计算，不是外部接口 | 盘中方向、活动净值和收益参考 |
| 夜间 PE 锚 | 乐咕/AKShare 沪深300 PE；腾讯沪深300收盘快照 | 夜间任务按时段重试，失败不覆盖旧 Gist | `pe_nightly.py → fm_pe_engine.json → localStorage`，前端 30 分钟拉取节流 | `peYest`、`priceYest`、`mcapYest`、`peSorted` |
| 用户配置 | 当前设备 localStorage | GitHub Gist 多端同步 | `fm_pe.json` 无版本；`fm_config.json` 带单调版本 | PE 档位、基金、持仓、预案 |
| 诊断日志 | 前端写入事件 | 无强一致保证 | `fm_log.json`，最多 200 条 | 排查多端覆盖和同步失败 |

### 数据源边界

- `DATA_MODE` **只控制盘中行情**：`direct` 浏览器直连腾讯；`gateway` 请求 `/v1/indices`。
- 官方净值始终请求 `NAV_BASE/v1/nav/today`，不受 `DATA_MODE` 影响。
- 前端不请求 `/v1/funds/estimate`，不读腾讯 `jj` 的历史估值块，也不使用 `fm_est.json`。
- `/v1/funds/official` 仅保留兼容和诊断；前端正式官方净值路径是采集器 KV。
- 公开第三方基金实时估值不是当前系统依赖。盘中显示为“代理”时，不代表真实基金净值。

## 2.5 运行时主链

冷启动时，指数、官方净值和云端配置三条链并发出发、互不等待，按各自到达顺序增量重画；
云端配置到达后仍会按既有语义跟随重算一次。首屏因此只受官方净值那一次往返制约。
这套时序有几条不会被测试保护的约束（启动块须同 tick、跟随刷新须排队而非丢弃），
见第三篇 §3.7。

```text
启动 / 每 10 秒 / 回到前台
  → fetchIndices()
  → direct：腾讯单次请求
     gateway：/v1/indices
  → setIndices()
  → 广播 INDICES
  → UI_updateIndices()
  → reapplyProxyEstimates()

启动 / 每 60 秒 / 回到前台 / 手动刷新
  → refreshData(force)
  → fetchOfficialData()
  → /v1/nav/today
  → fetchSingleFund()
  → applyProxyEstimates()
  → setLastResults()
  → 广播 FUNDS
```

官方净值批量缓存：

- 19:30 前缓存 1 小时；
- 19:30 后缓存 5 分钟；
- 已采全当日数据或周末缓存 12 小时；
- 当日只到部分基金时仍走 5 分钟；
- `force=true` 绕过批量缓存和采集器响应缓存。

任何基金条目读取失败时，从上一轮有效结果逐只回退并标记 `stale`。指数失败则优先使用
本设备指数快照并标记陈旧；gateway 还可先由服务端 `MARKET_LKG` 返回最近完整组。

## 2.6 官方净值窗口

采集器在北京时间工作日 09:00–24:00 每分钟运行：

```text
Gist fm_config.json 的 f
  → 5 分钟代码缓存
  → 缺行的基金：东财历史净值接口补最近两个净值日（补种）
  → 东财 + 腾讯并行抢当日净值
  → NAV KV
     nav:funds   每只基金一个条目，条目内最多两行
     nav:{date} / nav:today / nav:previous / nav:latest（旧模型，只作过渡兜底）
```

`nav:funds` 里 `funds[code].rows = [最新净值日, 前一净值日]`，行的身份是**净值自己的日期
（北京时间）**：滚不滚动、算不算今天、收益拿谁当基准，全部只看它。行内 `at` 的日期部分
恒等于该行日期，看板据它判净值日；真实抓取时刻另存 `gotAt`，只作诊断，不参与任何判断，
也不让补种行（`src: "history"`）参与 `first`/`firstCount` 的抢先评选。

由此得到三条不变量：新净值只在日期更晚时前插（只增不清）；每只基金自带两行，不依赖
“今天那份 / 昨天那份”的拼接；基金从看板删除即整条目删除。2026-08-05 晚间“新基金在官方
净值刷新期间整只消失”正是旧拼接模型的产物——今日记录一出现，读取口径整体切换，而新基金
不在被切过去的那一份里。新模型下这种消失不可能发生。

前端收益金额使用这两行事实，不从涨跌百分比反推基准。

具体 KV 写入、早退、基金列表跟随和部署方式见
[`workers/fund-nav-collector/README.md`](../workers/fund-nav-collector/README.md)。

## 2.7 Gist 同步

### 文件职责

| 文件 | 内容 | 冲突规则 |
|---|---|---|
| `fm_pe.json` | `p`：用户 PE 档位 `bucketStr` | 无版本号，用户变更即时推送 |
| `fm_config.json` | `v/f/h/s/pr`：版本、基金、持仓、降权预案、优先卖出 | 只采纳更高版本；本地更高则反向推送 |
| `fm_pe_engine.json` | 自动夜间 PE 引擎输出 | 自动任务写，前端只读 |
| `fm_log.json` | 本地和云同步诊断事件 | 非原子滚动日志，不承担状态同步 |

### 配置收敛

```text
本地配置写入
  → 对应 store 封装
  → bumpConfigVer()
  → localStorage
  → interact 显式 syncCloud("push_config")

冷启动/手动拉取
  → remote.v > local.v：导入云端
  → remote.v < local.v：把本地推回云端
  → 相等：不覆盖
```

冷启动时 PE 档位、配置、PE 引擎、连通性校验读的是同一份 Gist 文档，四次并发读取合并为一次 GET；
只合并在飞请求、不引入 TTL 缓存，`manualPull` 因此仍恒取最新内容。合并成立的前提见第三篇 §3.7。

`syncCloud("pull")` 的返回值只表示请求是否成功，不表示内容是否发生变化。日志清空不影响版本，
因为版本保存在配置本身。

## 2.8 市场网关

`gateway` 模式的行情路径：

```text
/v1/indices
  → 腾讯完整组
  → 失败后东方财富完整备组
  → 再失败读取 MARKET_LKG
  → 无 LKG 才返回 unavailable
```

主备不得按记录拼接。`force=primary|backup` 只供带诊断密钥的验收请求。网关的 Host、KV、
超时、缓存和接口契约见
[`workers/fund-market-api/README.md`](../workers/fund-market-api/README.md)。

默认 `DATA_MODE = "direct"` 是延迟选择，不代表网关无用：`/v1/nav/today` 始终在正式路径上，
`/v1/indices` 则保留为盘中行情的可切换容灾方案。

## 2.9 夜间 PE 引擎

```text
pe-night-trigger
  → repository_dispatch
  → .github/workflows/pe-night-engine.yml
  → automation/pe_nightly.py
  → 乐咕/AKShare沪深300历史PE
  + 腾讯沪深300收盘点位/总市值
  → Gist fm_pe_engine.json
  → 前端 pullPeEngine()
```

前端只消费：

- `peYest`
- `priceYest`
- `mcapYest`
- `peSorted`
- `date`

其中总市值路是默认主锚，点位路作为参考；选择开关是 `PE_ANCHOR`。这套自动数据锚与用户填写的
PE 档位 `bucketStr` 是两种数据，禁止在文档、存储或界面语义上混称。
