# 第三篇 · 实现约束

## 3.1 localStorage 封装

interact 层和 ui 层**禁止直接调用 `localStorage`**，所有读写通过 store 封装。

| 数据类型  | 读                                                           | 写                   | 清                    |
| --------- | ------------------------------------------------------------ | -------------------- | --------------------- |
| 基金列表  | `loadFunds()`                                                | `saveFunds()` ⚙      | —                     |
| PE 档位   | `loadPe()`                                                   | `savePe()`           | —                     |
| 持仓数据  | `loadHoldings()` / `loadHoldingsEquity()` / `loadShortNames()` | `saveHoldingsData()` ⚙ | —                   |
| 降权预案  | `loadSellPlan()`                                             | `saveSellPlan()` ⚙   | —                     |
| 优先卖出  | `loadPrioritySell()`                                         | `savePrioritySell()` ⚙ | `clearPrioritySell()` ⚙ |
| 配置版本  | `loadConfigVer()`                                            | `bumpConfigVer()`    | —                     |
| Gist 配置 | `loadGistConfig()`                                           | `saveGistConfig()`   | `clearGistConfig()`   |

> ⚙ = 该封装内置 `bumpConfigVer()`。**配置内容（f/h/s/pr）的每一个写入封装都必须自己自增版本**，
> 不许依赖「调用方会顺带调另一个会自增的函数」——`saveSellPlan` 就曾因唯一调用点紧跟在
> `saveHoldingsData` 之后而漏掉，属于随时会被下一次改动踩响的哑雷，2026-07-19 已补。

**授权例外**

- `syncCloud` push 路径直接读 `localStorage.getItem(STORE_HOLDINGS)` 跳过缓存，保证推送实时性。
- `importSnapshot` 内部直接写 `f/h/s/pr` 与配置版本号（不经 `saveSellPlan` 等封装，避免重复 `fmLog`），最后统一广播 `FUNDS` + `LOCAL_CONFIG`，避免双重渲染。

## 3.2 资金规则 → 代码映射

业务规则（1.5–1.6）落到 engine 的对应关系，改动须对照业务验证：

- **增权 `calcBuyPlanDraft`**：`buyAmt` = 缺口现金；`allocA500C = min(buyAmt, a500cRoom)`，`a500cRoom` 受 `LIMIT_A500C` 约束；`allocZZ500C` = 溢出，按 `isZZ500Product` 找承接品种。
  - ⚠️ `sharesA500C`/`sharesZZ500C` **除以兴全净值 `xqNav`**，因为业务关注的是「为各买入桶需**卖出的兴全份额**」，不是买入标的份额——**有意设计，勿改成除以 a500cNav**。
  - ⚠️ `totalFriction: 0` **有意设计**：增权标的为纯债（卖出端）和 C 类（买入端），均零摩擦，用户自行掌握。
- **降权 `calcSellExecutionDraft`**：三层优先级——中证500（`isZZ500Product`）→ `priorityCode`（用户标记）→ 其余按 `ratios` 比例。仅 `equity>0` 的品种参与。
- **档位目标 `getDynamicTarget(mode, bucketStr)`**：`buy` 取下一档、`sell` 取上一档、`neutral` 取本档。**边界兜底**：最低档增权或最高档降权时返回本档 target，业务合理，不是 bug。
- **实时 PE `getCurrentPE(peData, engineResult)`**：**不做插值**。`peData` 只承载 `bucketStr`，本函数只用它算跨档线（buyPct = lo − BUFFER_ZONE，sellPct = hi + BUFFER_ZONE）；PE 数值整个来自 `engineResult`（旁路引擎百分位）。引擎未就绪时 `value` 为 `undefined`，由 `ui-pe.js` 的 `Number.isFinite` 守卫落入「等待数据」。
  - ⚠️ 早年的「夜间录入三个点位 + `priceBuy/priceAnchor/priceSell` 分段线性插值」**已不存在**。
- **PE 锚定路径 `getAnchorPE` / `getRefPE`**：`config.js` 的 `PE_ANCHOR` 决定主路径——`"mcap"` 走 `getEnginePE1`（总市值路，默认），`"price"` 走 `getEnginePE`（点位路）。`getRefPE` 恒返回**另一条**，供 PE 栏小字并列展示。
  - ⚠️ **新增任何 PE 调用点一律走 `getAnchorPE`，禁止直接调 `getEnginePE` / `getEnginePE1`。** 2026-07-21 之前 PE 栏走 1.0、持仓抽屉走 2.0，同一份持仓两处 `isEquityWrongDir` 判定可能相反，PE 贴近 `PE_HIGH_THRESHOLD`(65) 时尤其容易撞上。
  - CSS 类名 `pe-bypass2` 是 `PE_ANCHOR="mcap"` 时代的遗留（那时小字恒为 2.0）；翻成 `"price"` 后小字变 1.0，类名语义反转。**已知，纯命名问题，不影响渲染，故意不动。**
- **方向异常 `isEquityWrongDir`**：高估区（PE ≥ `PE_HIGH_THRESHOLD`）权益偏低超 `EQUITY_DEV_LIMIT`，或低估区权益偏高超阈值。

**业务数字一律在 config.js**（顶层常量，按 §1–§10 分节）：费率 `FEE`、缓冲带
`BUFFER_ZONE`、阈值 `PE_HIGH_THRESHOLD`/`EQUITY_DEV_LIMIT`、代码
`CODE_XQ`/`CODE_A500`/`IDX_PE`、上限 `LIMIT_A500C`、时点 `T_*`/`T_OFF_UPDATE`、
默认档位 `DEFAULT_BUCKET`、12 档表 `PE_EQUITY_TABLE`、模式开关 `DATA_MODE`/`PE_ANCHOR`。
新增业务数字不得散落他处。

**`DEFAULT_CODES` 恒为空数组，不许再往里塞产品。** 真实基金列表跟着 Gist
`fm_config.json` 的 `f` 走，这个常量只在没有任何本地配置的新设备上生效一次。写死名单
会悄悄过期——退役的 `007466` 曾一直留在里面，而采集器按 Gist 列表工作、根本不采它，
于是新设备首屏固定挂一行「⚠ 获取超时」。空列表走 `ui.js` 既有空态「暂无关注产品」，
加一只即有数（实测无 `NaN`、无控制台报错）。同理 `NAMES`/`SHORT_NAMES`/`PRODUCTS`
只登记在册产品，退役即删。

## 3.3 engine 净值/档位取值规则

**净值选取分两类口径**。曾经写成“三处逐字一致”，把两种口径捆在一起，
结果盘中估算断供时把上一交易日的涨跌当成今日收益发了出去。**先分清在算什么，再决定用哪条判据。**

| 口径 | 位置 | 判据 | 为什么 |
| --- | --- | --- | --- |
| **市值**<br>持仓值多少钱 | `data.js` `getNavByCode` | `f.offVal && (!estD \|\| offD >= estD)` | 要**最新可得**净值，哪天的都对。盘中通常取代理，官方落地后自动切回，权益和总额因此能跟随大盘 |
| **收益**<br>今天赚了多少 | `engine.js` `calcFundProfit` / `calcTodayProfit` / `calcProfitMap` | **唯一金额公式**：`份额 × (活动净值 - 基准官方净值)`。交易日官方未披露用代理净值与最新官方净值；官方披露后用今日官方净值与前一官方净值；非交易日用最近官方净值日与其前一官方净值日 | 金额围绕份额和两次净值差计算，百分比只作展示派生，绝不反推金额 |

⚠️ **顶部与抽屉必须共用同一个纯收益函数。** `interact.js` 不再允许复制收益判据；
抽屉逐只收益经 `calcProfitMap` 出，顶部汇总经 `calcTodayProfit` 出，两者底层都调用 `calcFundProfit`。

⚠️ **基准代理不在这两处分叉**。代理值由 `refreshData` 在 `setLastResults` 前填进
`results` 的估算位，两处看到的都是同一条净值链，各自不带代理分支。
**不要再往这两个函数里加取值分支**——要改代理行为，改 `applyProxyEstimates` 一处即可。

⚠️ **市值口径那条的 `!estD ||` 半边不能省。** 曾写成 `estD && offD && offD >= estD`，要求先有估算才肯用官方；
估算整组不可用时所有 `estVal` 同时为 null，持仓市值便整体算不出来。2026-07-19 已修正。

**“已更新”徽标**：由 `calcTodayProfit` 的 `isRealUpdate` 驱动 `allUpdated` → 顶部徽标。
它与净值选取分开，原则是“数值可以合理回退，状态必须严格”。
- ⚠️ **代理不算“已更新”**：`isRealUpdate = isOffToday || (isEstToday && estSource !== "proxy")`，
  与取值用的 `isFundUpdated`（含代理）刻意不同。看着像重复判断，其实语义不同——
  代理是拿昨日净值乘指数推的，一条真数据都没到；若徽标沿用 `isFundUpdated`，
  估算源全死的日子里它会天天亮着，等于永久说谎。**别"顺手"把这两个合并回一个变量。**

**顶部「最新收益」的显示**：`calcTodayProfit` 返回 `isWaitingForData`，
为真时顶部显示 `-`。三种情形——盘前集合竞价、有持仓但无一只拿得出今日数据、整组请求失败。
**有持仓就是有持仓，不因请求失败而变空白**：空白看起来像"没有持仓"，正确表达是"有持仓但此刻不知道"。

**盘中估算列的正式口径是基准代理**（`estSource === "proxy"`，由自定义基准权重 × 实时行情推出），
不是真实基金估值。
盘中行情由 6 个可见指数和 4 个隐藏估算因子组成；隐藏因子不参与顶部展示，也不是官方净值。

**官方净值 TTL（`fetchOfficialData`）**：官方数据按基金列表整体缓存；19:30
（`T_OFF_UPDATE`）前 1 小时 / 后 5 分钟 / 已是当日数据且采全或周末 12 小时。
**半成品**（今日数据但 `data.size < codesCount`）走 5 分钟短缓存等补采，不锁 12 小时。
`force=true` 绕过 `officialBatchCache` 和 `_navCollectorCache`，刷新按钮使用，定时器和
`visibilitychange` 不使用。

**前端逐只 LKG 回退（与 `DATA_MODE` 无关）**：
- **触发条件**：`refreshData` 主流程中，`fetchSingleFund(code, official)` 返回 `error:true`，且 `getLastResults()` 中存在该 code 的上次有效数据（`!error && offVal`）。
- **回退动作**：从 `getLastResults()` 取出整条记录，修改 `offSource` 为 `"stale"` 后填入 `merged`。LKG 回退发生在 `applyProxyEstimates` 之前，因此代理值可基于回退的 `offVal` 重算。
- **`offSource:"stale"` 标签**：复用 `ui.js` `srcTag()` 的 `"陈旧"` 分支（第 70 行）；`pickWinnerTag` 因 `SRC_LABELS` 无 `stale` 键而自动跳过，不影响抢先源标签。UI 层零改动。
- **与网关 stale 的区别**：网关 `stale` 是盘中行情整组不可用时的整体回退；本处 LKG 是
  **官方净值逐只回退**——某只采不到只回退那一只，其他基金继续用新鲜数据。

**估算持久化已删除。**
盘中估算列只保留基准代理：`BENCHMARK_PROXY × 实时指数涨跌 × 基准官方净值`。
代理支持完整降级模型：主模型任一行情腿缺失时整套切换 `fallbackLegs`，主模型和降级模型都不完整时返回空值，禁止半套混算。
旧的真实估算请求、本地估算 localStorage、`fm_est.json` Gist 快照、`baseNav/baseDate` 缓存路径均不得恢复。
恢复这些路径会重新引入“陈旧缓存把多日净值差当单日收益”的错数风险。

## 3.5 样式约定

- **字体**：数字加 `class="num"`（`--f-num`），中文用 `--f-zh`，禁止遗漏。
- **颜色**：全部用 CSS 变量，禁止硬编码 hex/rgb/具名色。唯一例外：遮罩层 `rgba(0,0,0,0.6)`。
- **字重**：只用 400 / 500 / 600，禁止 700。
- **动态 `<input>`**：必须声明字体、背景、边框、文字颜色（不继承父级）。
- **网格边框**：容器 `gap:1px` + 边框底色，单元格设卡片底色，天然细线；禁止 `:nth-child` + `border` 覆写。
- **抽屉 Tab**：`tabStyle` 用 `var(--bg3)`；增权 Tab 用 `var(--buy-bg)`、降权用 `var(--sell-bg)`；卡片体统一 `var(--bg3)`，方向感由数字颜色和边框传达。
- **护眼模式**：低饱和度护眼调色盘，`<meta name="darkreader-lock" />` 防外部劫持；除 `--up/--dn` 外禁止高亮纯白。

## 3.6 ui 三文件关键约定

- **DOM 缓存**：高频静态节点通过 `_getEl(id)`，禁止在渲染循环内直接 `getElementById`。
- **`_peDOMReady` flag**：控制 `_peDOM` 一次性初始化，禁止用 `!_peDOM.display` 判断（display 为 null 时误判）。
- **`UI_render*` 工厂**：只返回 HTML 字符串，DOM 写入由 interact 负责。
- **`UI_buildSummaryHtml` 签名**：`(currentPE, eqData, currentEqVal, eqCol, targetNeutralNum, inDrawer=false)`，`inDrawer=true` 自动输出抽屉样式。
- **`UI_buildHoldingPlanHtml` 签名**：`(activeProds, targetEqNeutral, eqData, buyDraft, sellDraft)`。`eqData` 由 `liveUpdateHoldingPlan` 计算后传入，ui 层禁止自行调 `calcCurrentEquity`。

> **唯一例外 · PE 栏只读展示**：`ui-pe.js` 的 `updatePeBar` 直接调用 `calcCurrentEquity` /
> `getDynamicTarget` / `isEquityWrongDir` / `getBoundaryPrices`，与本节及 [02-系统架构.md](02-系统架构.md)
> §2.2「ui 层禁止业务计算」相抵触。
>
> **为什么开这个口子**：PE 栏挂在 `INDICES` 频道上，每 10 秒随指数刷新；若按常规交由 interact
> 预算再传入，就要为这条 10 秒链路单开一个调度函数并改动 Observer 接线，**代价大于收益**。
>
> **边界**：仅限只读展示，**不得写 store、不得触发同步**。这是白名单，不是先例——
> 其他 ui 文件仍然禁止业务计算。
- **`renderTodayProfit` 签名**：`(results, holdings, activeProds, mktState, todayStr)`，
  `holdings` 与 `activeProds` 由调用方传入。不需要 `indicesMap`——代理值已在 `results` 里。
- **给视图新增跨频道依赖时，必须接上那条频道的重画线**：
  `INDICES` 频道除 `UI_updateIndices` 外还调 `reapplyProxyEstimates`，后者经 `setLastResults`
  广播 FUNDS 触发重画。漏接的表现不是报错，而是净值先于指数到货的那一轮渲染完就永久静止
  （顶部卡在 `-`、权益%冻结），要等 60 秒后的下一次净值刷新才恢复。
- **`applyProxyEstimates` 必须幂等**：代理条目可以被下一次指数 tick 覆盖重算，指数涨跌才会连续传导到权益%/持仓总额/收益。
- **代理净值必须只用官方净值作基准**：
  - `offDate < quoteDate`（白天官方最新值仍是上一净值日）：`estVal = offVal × (1 + proxyPct)`。
  - `offDate === quoteDate`（夜间当日正式值已发布）：`estVal = previousNav × (1 + proxyPct)`。
  - `offDate > quoteDate` 或缺少官方基准：不重算，不让陈旧指数制造新估值。
  禁止用 `offPct` 反推 `previousNav`，否则百分比精度会重新污染金额计算。
- **卡片左侧色条**：`renderCards` 用 `getActivePct()` 定 `up-card`/`down-card`。折叠态卡片上只露一个数字，
  而那个数字由 `miniMode`（0=估算 / 1=官方 / 2=并列）决定，两者口径可能不同——**已知不一致，待定**，
  改动前先与用户确认，不要自行对齐。

## 3.7 冷启动时序与请求收敛

首屏耗时曾经是「云端配置一次往返 + 官方净值一次往返」串行相加（实测约 3 秒）：
`main.js` 先 `syncCloud("pull")`，而 `syncCloud` 内部拉完才 `await refreshData()`。
2026-08-04 改为并发出发，卡片此后只受官方净值那一次往返制约。下面四条是这次改动留下的
反直觉约束，**破坏其中任何一条都不会有测试报警**，只会悄悄退回慢速或错误行为。

**① `main.js` 的启动块必须整块留在同一个同步 tick 内**

`fetchIndices` / `refreshData` / `syncCloud("pull")` / `pullPeEngine` / `_verifyCloudConfig`
连续调用，中间不许插入 `await`、`.then` 或 `setTimeout`。后三者读的是**同一份 gist 文档**，
而 `data.js` 的 `_readGistDoc` 只合并「在飞中」的请求——任何一处被推迟到下一轮事件循环，
就会自己再发一次全量 GET。改动前这四处各发一次，冷启动重复下载 4 份完整文档
（每份都含数千点的 `peSorted`，约 90KB），还与官方净值请求抢移动网络带宽。

**② `_readGistDoc` 只合并在飞请求、不加 TTL 缓存 —— 有意设计**

看着像「顺手加个 30 秒缓存更省」，但 `manualPull` 必须永远拿到最新云端配置：加 TTL 就会让
用户在另一台设备改完、立刻在这台点拉取时拿到旧值。合并只发生在同一 tick 的冷启动窗口内，
不产生任何陈旧风险。

**③ `refreshData` 的并发调用是「排队一次」，不是「丢弃」；队列里的 `.catch` 不可省**

并发化后出现新窗口：云端配置晚到并换掉基金列表时，那次重算会撞上启动那轮仍在飞的刷新。
旧的 `_isFetchingData` 守卫直接丢弃调用，列表就纠正不过来，得等 60 秒定时器。现在改为最多
排队一次跟随刷新（官方净值有 `NAV_COLLECTOR_TTL` 节流，跟随刷新通常不产生新请求，只是按新
列表重算重画）。
⚠️ 队列里 `_refreshInflight.catch(() => {}).then(...)` 的 `catch` **不是防御性冗余**：去掉后，
在飞那轮一旦抛错（渲染层异常即会），`.then` 回调不执行，`_refreshQueued` 会永久停在那个已拒绝
的 promise 上——此后 `!_refreshQueued` 恒假，整个会话再也排不进跟随刷新，并把旧的拒绝抛给
`syncCloud("pull")`，连带 `manualPull` 的成败提示一起失灵。已在浏览器实测复现，勿简化。

**④ `_verifyCloudConfig` 的连通判据是「文档取到且可解析」，不再看 HTTP 状态码**

改判据不是为了语义，而是为了让它能并入 ① 的合并；对 2/2 指示灯的效果与原来等价。

**首屏不做本机净值快照预渲染**，理由属业务边界，见
[docs/01-业务意图.md](01-业务意图.md) §1.1 末段。

## 3.8 日志诊断系统（logger.js）

记录本地写入与云端推送（时间戳、客户端标识、函数名、数据快照），写入主 Gist 的
`fm_log.json`，最多 200 条滚动覆盖（约 10 天）。未配置 Gist 时静默跳过。

**配置**：与主 Gist 共用 `GistID,Token`，首次使用前须在主 Gist 手动添加 `fm_log.json`，初始内容 `[]`。

**接入点（10 处）**：store.js 的 `saveFunds`、`savePe`、`saveHoldingsData`、`saveSellPlan`、`savePrioritySell`、`clearPrioritySell`、`importSnapshot`（记录 `v/f/h/s/pr`）、`importPeSnapshot`；interact.js 的 `syncCloud_push_pe`、`syncCloud_push_config`（含版本号 `v`）。

**已知限制**：`fmLog` 为非原子的「GET 整份 → push → PATCH 整份」，同瞬两个 `fmLog` 会竞争同一文件、后者覆盖前者。配置版本机制落地后 import 已幂等、并发写日志极少，实务无影响；若需绝对可靠可改串行队列，非必需。

**停用**：删除 `logger.js`、删除 `index.html` 中的 script 标签、删除 store.js 与 interact.js 中所有 `fmLog(...)` 调用行。
