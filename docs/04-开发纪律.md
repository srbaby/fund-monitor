# 第四篇 · 开发纪律

> 本篇只规定如何审查、修改、验证和交付。业务规则以第一篇为准，架构事实以第二篇为准，
> 代码判据以第三篇为准。

## 4.1 先判断，再动手

发现疑似问题时依次完成：

1. **业务验证**：它是否可能是有意规则，例如增权份额除以兴全净值、代理不点亮“已更新”。
2. **数据验证**：使用真实返回形状或最小可复现样例，不用想象中的上游字段推断。
3. **影响验证**：说明什么输入下，用户会看到什么错误结果。

无法回答第三项时，只能记为风险或疑问，不能直接认定为缺陷。

## 4.2 改动原则

- **最小影响范围**：先找根因和唯一职责位置；跨层修改时说明每一层为什么必须一起变。
- **改原处**：不在外围叠加新 `if`、影子状态或重复算法来掩盖旧错误。
- **删干净**：不再调用的函数、变量和路径直接删除；不保留“以后可能用”的僵尸代码。
- **新增能力允许净增代码**：交付时如实说明文件和行数范围，不以压行数制造伪合规。
- **参数集中**：费率、阈值、基金/指数代码、权重、时点和模式开关只放 `js/config.js`。
- **结构改动先确认**：新增/删除文件、改目录、重分层、替换数据源、删除反直觉机制前，
  先说明影响边界并取得用户确认。
- **审查和实施分开**：用户只要求审查时，不自动修改；用户要求修复时，完成相称验证后交付。
- **历史留给 Git**：正文不维护流水账、旧文件沿革或已作废的方案。

## 4.3 关键实施纪律

1. **分层单向**
   - 保持 `config → store → data/engine → ui → interact → main`。
   - engine 外部状态通过参数传入。
   - UI 不写 store、不触发云同步；`ui-pe.js` 的只读白名单不得扩大。

2. **状态写入**
   - interact/ui 不直接操作业务 localStorage。
   - 基金、持仓、降权预案、优先卖出通过 store 封装写入。
   - `f/h/s/pr` 每条写入封装自行调用 `bumpConfigVer()`，不能依赖调用链中别的函数顺带自增。
   - `saveFunds()` 后由广播驱动刷新，不手动复制一套渲染链。

3. **云同步**
   - 用户配置变化由 interact 显式调用 `syncCloud`，不挂在 Observer 上自动推送。
   - PE 档位用 `push_pe_now`；基金/持仓/预案用 `push_config`。
   - `importSnapshot` 仅在 `remoteV > localV` 时导入；本地版本更高时允许反向自愈。
   - `syncCloud("pull")` 返回值表示拉取成败，不表示配置是否变化。

4. **数据源**
   - 官方净值只读 `/v1/nav/today`，不受 `DATA_MODE` 影响，不加浏览器直连兜底。
   - `DATA_MODE` 只控制盘中行情：`direct` 浏览器腾讯；`gateway` 走 `/v1/indices`。
   - 不恢复 `/v1/funds/estimate`、腾讯基金历史估值块、`fm_est.json` 或估值 localStorage。
   - 引入浏览器新来源前必须验证 CORS；不能靠伪造受限请求头绕防盗链。

5. **行情和代理**
   - direct 和 gateway 都保持单次批量行情请求。
   - 6 个核心指数的完整性判据不因隐藏因子增加而放宽。
   - 代理主模型缺一腿时整套切 `fallbackLegs`；禁止主备腿混算。
   - 代理基准只来自官方净值窗口，禁止用百分比反推净值。
   - `applyProxyEstimates()` 必须幂等，指数更新后能安全重复重算。

6. **净值和收益**
   - 市值使用最新可得净值。
   - 收益只走 `calcFundProfit`，金额固定为 `份额 ×（活动净值 − 基准官方净值）`。
   - 顶部和抽屉共用该函数，不在 interact 复制判据。
   - 代理不算真实更新；旧值必须显式标记陈旧。

7. **异常与异步**
   - 极端输入返回 `null` 或 `{ error: true }`，不让 `NaN`/`undefined` 流入渲染层。
   - 单次请求失败不清空已有持仓、净值或行情。
   - Worker 的 `scheduled` / `waitUntil` 链保留 `.catch()` 和可定位日志。

8. **界面**
   - 动态数字元素带 `class="num"`。
   - 颜色使用 CSS 变量；字重只用 400/500/600。
   - 动态 `<input>` 显式声明字体、背景、边框和文字颜色。
   - Sortable 重建前销毁旧实例。

9. **新增一只基金**
   - 在 `js/config.js` 的 `BENCHMARK_PROXY` 登记代理权重；没有产品知识库依据时不猜基准、不加自动降级。
   - 确认云端基金列表 `fm_config.json` 的 `f` 字段已同步，避免采集器仍按旧列表工作。
   - 加入后一分钟内检查 `/v1/nav/today`：该代码应已由补种带出两行（当前净值 + `previousNav`），不必等当晚。
   - 同步补代理回归、采集器补种/当日判据和读端点抢先统计测试，再更新对应组件文档。

## 4.4 验证矩阵

| 改动范围 | 最低验证 |
|---|---|
| `BENCHMARK_PROXY`、行情因子、代理算法 | `node --test test/proxy-estimate.test.mjs` |
| `fund-market-api` | `node --test workers/fund-market-api/test/gateway.test.mjs` |
| `fund-nav-collector` | `node --test workers/fund-nav-collector/test/collector.test.mjs` |
| JavaScript 运行时代码 | 对所有改动的 `.js/.mjs` 运行 `node --check` |
| 文档、配置、工作流 | 搜索失效链接/旧端点/旧术语，并运行 `git diff --check` |
| 页面呈现或交互 | 本地打开页面，检查桌面和移动主视图及控制台 |

测试通过只是部分证据。涉及重要不变量时，还要补反例：

- 主模型缺一腿是否整套降级；
- 主模型和降级模型都不完整时是否返回空；
- 官方净值只有一日时是否拒绝算收益金额；
- 行情失败时是否保留旧值并显示陈旧；
- 新增隐藏因子后顶部是否仍只显示 6 个指数；
- 某只基金今天还没出净值时，读端点是否仍完整返回它自己的两行（2026-08-05 消失事故）；
- 补种回来的旧净值，对外时间戳是否仍挂在净值自己的日期上，而不是抓取当天；
- 补种条目是否被排除在读端点的抢先统计之外。

## 4.5 交付清单

**范围**

- [ ] 改动符合用户授权，没有顺手补未批准功能
- [ ] 结构性改动已确认，未覆盖用户无关工作区修改
- [ ] 每项修改都能指向唯一职责文档或代码层

**逻辑**

- [ ] 业务参数集中在 `config.js`
- [ ] 配置写入通过 store，版本按路径自增
- [ ] 取数没有跑出既定 direct/gateway/官方净值链
- [ ] 市值、收益和“已更新”三种语义没有混用
- [ ] 代理主降级模型保持完整切换
- [ ] 异常不会清空已有有效数据

**验证**

- [ ] 相关专项测试通过
- [ ] 改动脚本语法检查通过
- [ ] 页面/接口验证与风险相称
- [ ] `git diff --check` 通过
- [ ] 文档中的接口、测试数、基金和指数代码与仓库当前实现一致

**交付说明**

- [ ] 先给结论，再列实际修改和验证证据
- [ ] 明确是否部署、提交、推送
- [ ] 有未决风险时写清影响和下一步，不用历史流水账代替结论
