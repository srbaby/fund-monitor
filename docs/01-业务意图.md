# 第一篇 · 业务意图

> 本篇回答「看板为什么存在、每个功能为什么这么设计」。所有计算、信号、字段的存在都服务于一个目的：**让一套以估值为锚的机械配置纪律，在盘中可被肉眼观察、被准点提醒、被精确算量**。读懂本篇，才能判断某段代码是不是「有意设计」。

## 1.1 看板的核心价值

**一句话**：一个盯盘观察 + 信号提醒 + 操作量计算的辅助决策工具。它不替用户决策，也不下单——它把抽象的估值纪律，变成盘中看得见、催得动、算得准的三件事。

```
观察：实时把市场估值（PE 百分位）摆在眼前，并标出「现在偏离目标多远、朝哪个方向」
提醒：只在估值跨过纪律阈值时给出增权/降权信号，其余时间明确告诉用户「无需动作」
算量：一旦该动，直接倒推出「卖哪只、买哪只、各多少份、磨损多少」的可执行数字
```

**为什么是这三件事**：用户的投资纪律是「以 PE 估值机械触发、不预测、不主观择时」。这条纪律的最大敌人不是看不懂市场，而是 ①盘中算不清此刻该不该动、②情绪驱动的无信号操作、③真要动时算份额容易出错。看板就是为消解这三个痛点而生——**它的价值不在「执行」，而在把纪律的判断与算量从大脑搬到屏幕上，让用户只需照着结果手动下单。**

**因此看板刻意不做的事（边界，勿擅自补成「功能缺失」）**

- **不执行、不连券商**：执行始终是人工动作。看板越界自动下单，就违背了「机械出信号、人工担责执行」的设计。
- **不替用户决策**：看板只摆事实、给信号、算份额；要不要动、动多少最终由人确认。这是「纪律 > 聪明」在产品形态上的落地。
- **不管 QDII / 全球配置**：那是与 A 股估值引擎完全解耦的另一套体系，掺进来只会污染 PE 信号的纯粹性。
- **不做枷锁层日常调度**：枷锁层是长期持有的「装死」底仓，本就不该被日常 PE 波动驱动；看板只在用户显式标记或填权重时才把某只纳入降权计算。
- **不判定 T+7 成熟份额、不实现黑天鹅静默/破窗等执行细则**：这些属于人在交易端的临场判断，看板只提供算量依据，不代行判断。

**因此对数据可信度有一条硬要求：陈旧可以接受，陈旧且不告知不行。**
看板是用来决定「此刻要不要下单」的。行情拿不到新的，就继续显示上次那份好数据——
**但必须明确标出它是旧的**。把昨天的数当今天的显示，比显示空白更危险：空白只是让用户查不到，
而无声的旧数据会让用户**基于错误前提下单**。同理，任何一次取数失败都不许把已有数据清空——
用户看到一片空白会以为「我没有持仓」，而正确的表达是「有持仓，但此刻不知道值多少」。

**但这条不反向成立：首屏宁可晚半秒，也不抢先画一个本次没被确认过的数字。**
2026-08-04 做首屏提速时评估过「打开瞬间先用本机存的上次净值把卡片画出来、标注陈旧，
网络到货再替换」，能把卡片出现时间从约 1 秒压到 0.2 秒——**已否决，不要再提议**。
首屏是用户当天的第一眼，那一眼看到的数字最容易被直接当作决策依据，标注再明确
也敌不过「一打开就看见数字」本身的暗示。所以卡片一律等本次官方净值到货再画，
在那之前显示的是初始化占位，不是任何净值。
（刷新失败退回上次好数据并标注陈旧是另一回事：那时用户已经看过本次确认过的数，
知道自己面对的是一块持续运行的看板，而不是刚打开的一屏。）

## 1.2 看板凭什么观察：实时 PE 锚定

**要解决的现实矛盾**：纪律要求「用今日真实 PE 决定动作」，但官方 PE 当晚才发布，而基金交易 14:50 就截止——盘中根本拿不到权威 PE。

**看板的解法**：把「夜间定锚」与「盘中比例外推」接力。**两步都是自动的，用户只需要录一个档位区间。**

- **夜间定锚（引擎自动，非人工录入）**：`automation/pe_nightly.py` 由 GitHub Actions 在夜间抓取乐咕的沪深300 滚动 PE，写入 Gist `fm_pe_engine.json`。前端只消费其中 5 个字段：`peYest`（昨收官方 PE）、`priceYest`（昨收点位）、`mcapYest`（昨收总市值）、`peSorted`（全量历史 PE 升序数组）、`date`。
- **盘中比例外推（看板计算）**：拿沪深300 的实时快照，按比例把昨夜的锚推到此刻——

  ```
  1.0 总市值路（默认）：实时PE = peYest × (实时总市值 / mcapYest)     ← getEnginePE1
  2.0 点位路（参考）  ：实时PE = peYest × (实时点位   / priceYest)    ← getEnginePE
  ```

  再把算出的实时 PE 拿到 `peSorted` 里二分查找，得到**历史百分位**——这个百分位才是一切信号的输入。走哪条路由 `config.js` 的 `PE_ANCHOR` 决定，另一条自动降为 PE 栏小字参考。

**为什么这样设计**：用户盘中拿不到官方 PE，但拿得到实时总市值/点位。只要夜里把「昨收 PE ↔ 昨收总市值」的对应锚死，盘中一个比例就能推出当下 PE。**这正是看板作为盯盘工具的立身之本——没有它，纪律在盘中无法落地。**

**为什么默认走总市值路**：曾用 15 个交易日逐日比对收盘口径，1.0 平均绝对误差
0.41pp、最大 0.86pp、误差超 1pp 的天数 0/15；2.0 分别是 1.31pp / 3.69pp / 6/15。
**但 2.0 保留而非删除**——成分调整日总市值会跳变，那种日子点位路反而是有效参照，
故做成可切换而不是写死。

> **用户在看板上只录一个数**：当前 PE 档位区间（如 `65,70`），即 `savePe({ bucketStr })`。
> 点位、PE、百分位全部由引擎供给，无需人工录入。**早年那套「夜间录入收盘点位/增权点位/降权点位 +
> 盘中分段线性插值」已被取代**，若在旧文档或旧对话里见到，以本节为准。

**目标 PE / 实时 PE / 跨档线 三个概念**（后文反复用到）：

- **实时 PE**：上面外推 + 二分查得的当下估值百分位，是一切信号的输入。
- **目标总权益**：实时 PE 经 12 档映射得到的「此刻应持有多少权益仓位」（见 1.3）。
- **跨档线（触发线）**：当前档位上下边界各外扩一个缓冲带后的两条 PE 线（见 1.4）；实时 PE 越过它才算「真跨档」、才给信号。

## 1.3 看板凭什么算目标：12 档 S 曲线

**功能定位**：这张表是「实时 PE → 目标总权益」的唯一换算依据。看板每次刷新都用它把当下估值翻译成「现在该持有百分之多少的权益」，再与实际持仓比对得出偏离。**没有这张表，看板就无法回答「现在偏离目标多远」——观察功能就空了。**

| 市场 PE 档位 | 目标总权益 | 该档看板给用户的潜台词           |
| ------------ | ---------- | -------------------------------- |
| > 80%        | 20.0%      | 极度泡沫，锁死底仓               |
| 75–80%       | 22.5%      | 泡沫期，极缓收割                 |
| 70–75%       | 25.0%      | 退潮，平稳撤军                   |
| 65–70%       | 27.5%      | 高位警戒，回流资金（当前基线档） |
| 60–65%       | 32.5%      | 偏高，开始抽水                   |
| 55–60%       | 42.5%      | 收割带，下手要狠                 |
| 50–55%       | 50.0%      | 重心区，套利最大化               |
| 45–50%       | 57.5%      | 收割带，吸廉价筹码               |
| 40–45%       | 62.5%      | 深水区，可上弹性品种             |
| 35–40%       | 70.0%      | 逼近极限，活塞水位预警           |
| 30–35%       | 75.0%      | 危机区，强换进攻                 |
| < 30%        | 80.0%      | 深渊，满仓博反转                 |

**曲线形状本身就是设计意图**，看板的行为因此天然疏密不同，这点要让 AI 理解：

- **头部钝化（PE>70 步长极小）**：高位时相邻档目标权益只差 2.5%，意味着看板在高位给出的减仓量很小——刻意防止把最后的底仓和利润卖飞。
- **腰部暴力（PE 45–60 步长最大）**：估值合理偏低时相邻档目标差 7.5%–10%，看板给出的操作量最大——这是收益的主来源，看板在此最「活跃」。
- **尾部钝化（PE<35 步长收缩）**：极低位时再次收窄，看板给出的加仓量受控——防止在真正的大底前过早打光弹药。

> 此表即 `config.js` 的 `PE_EQUITY_TABLE`。它是投资方法论的产物，**改动须由用户基于方法论决定，AI 不在看板侧擅自改数**。

## 1.4 看板凭什么提醒：缓冲带与跨档触发

**要解决的问题**：若 PE 一碰档位边界就提醒，估值在边界反复横跳时看板会狂发信号、诱发来回操作——这恰是用户要避免的「交易摩擦吞噬收益」。

**看板的解法——缓冲带 ±1.75%**（`BUFFER_ZONE`）：在当前档位的上下边界各外扩 1.75%，形成两条**跨档线**。实时 PE 只有真正越过跨档线，看板才判定「跨档」并给信号：

- 实时 PE > 本档上边界 + 1.75% → 降权信号（估值偏高，该减仓）
- 实时 PE < 本档下边界 − 1.75% → 增权信号（估值偏低，该加仓）
- 跨档后按新档边界重算缓冲带

**这个缓冲带承载三层提醒纪律**，是看板「只在该动时才催」的关键：

- **防边界震荡**：估值在档位边界附近抖动时不触发，避免来回操作。
- **防接飞刀**：暴跌一次跨 2 档，也只触发 1 次增权信号——强制分批，不让用户一路买到底。
- **防追涨**：暴涨一次跨 2 档，也只触发 1 次降权信号——保住底仓，不追着卖。

**装死 vs 触发**：看板对外只有两种态度——未跨线就明确显示「对齐、无需动作」（对应用户纪律里的「装死」），跨线才高亮信号。**让用户绝大多数时间看到「不用动」,正是看板在帮用户对抗手痒。**

## 1.5 看板凭什么算量：权益填补倒推法

**目标**：信号出现后，看板要回答「具体卖哪只、买哪只、各多少份」。它用一个会计恒等式倒推：

```
[ 枷锁层权益贡献 ] + [ 可调度层补充 ] = [ 当前 PE 目标总权益 ]
```

- **枷锁层 = 固定底色**（鹏华丰利 / 易方达回报 / 海富通混合 / 博道300增强C 等，≈75% 基线）：长期持有不动，贡献一块相对稳定的权益。看板把它当常量，**不主动调度**——因为它的价值在长期 Alpha，频繁动它就是摩擦。每只对总权益的贡献 = 实际占比 × 其「档位」(权益敞口系数)。
- **可调度层 = 零摩擦活塞**（A500C / 中证500C / 兴全中长债，统一 C 类、T+7 零摩擦）：承担**全部** PE 跨档的权益调节。看板的增降权算量只在这一层动手。

**为什么分两层**：把「该动的」和「不该动的」在数据结构上分开，看板才能既算准总权益、又只对零摩擦的活塞层下手——这是「操作策略 > 选品 Alpha」「低摩擦优先」在产品里的体现。

## 1.6 看板凭什么给份额：资金调度规则

信号方向定了，看板按固定优先级把「权益缺口」翻译成具体份额：

**增权（缺口 Gap = 目标权益 − 当前权益，需把资金转成权益）**

1. **资金来源固定为卖出兴全中长债**（`CODE_XQ`）——它是零摩擦的资金活塞，专门干这个。

   > **增权份额报的是「卖多少兴全」，不是「买到手多少份」。** 用户的实际操作顺序是
   > **先赎回兴全、再拿钱申购**，手里真正要输入到交易软件里的数字，是那笔**赎回份额**。
   > 所以各买入桶的份额一律除以**兴全净值**换算，而不是除以买入标的自己的净值。
   > ⚠️ 这一条看起来像单位用错了，是有意的，勿"修正"。
2. **优先买 A500C**（`CODE_A500`），但单品占总资产不超过 `LIMIT_A500C`（20%）——主力 Beta 工具，但要防单品集中。
3. **溢出买中证500C**：缺口超出 A500C 上限的部分，转投持仓中名称含「中证500」的品种（`isZZ500Product` 动态按名称识别，不硬编码代码，便于换券）——它是极端低估时的弹性武器。

**降权（需把权益转回资金）按三层优先级减仓**

1. **中证500 品种**（按名称自动识别，最高优先）——先撤弹性最大的。
2. **用户手动标记的优先卖出品种**——把临场判断权交给用户。
3. **其余按用户填的权重比例减仓**——兜底分摊。

**摩擦模型**：`FEE`（0.5%）只对混合型品种（权益系数 `∉ {0,1}`）计提；纯债（系数 0）与纯股 C 类（系数 1）零摩擦。**看板据此在降权预案里如实显示「交易磨损」，让用户看见每次操作的代价**——这是用产品手段强化「摩擦敏感」纪律。

**调仓用哪一档的目标**：看板算调仓量时，用的是**跨档后**的目标档而非当前档——增权看下一档、降权看上一档、纯展示资产权益时看当前档（见 `getDynamicTarget`）。因为信号一旦触发，意图就是迁移到新档位，算量自然该对齐新目标。

## 1.7 看板的整体数据流（把上面串起来）

```
夜间引擎自动写 Gist fm_pe_engine.json：peYest / priceYest / mcapYest / peSorted
用户只录：档位区间 bucketStr（如 "65,70"）
        │
        ▼
盘中沪深300 实时快照 ──┐
（总市值 或 点位）      ├─→ 比例外推 → 二分查 peSorted → 实时 PE 百分位（1.2）
夜间锚 peYest 等 ──────┘   走哪条由 PE_ANCHOR 决定（getAnchorPE）
        │
        ▼
实时 PE ──→ 12 档 S 曲线 ──→ 目标总权益（1.3）
        │
        ├─→ 当前持仓权益（calcCurrentEquity）→ 偏离方向/幅度 → 染色 + 跨档判定（1.4）
        │
        ├─→ 增权预研（calcBuyPlanDraft）：卖兴全 → 买 A500C/中证500C 各多少份（1.5/1.6）
        │
        └─→ 降权预案（calcSellExecutionDraft）：三层优先级下各品种卖出份额 + 磨损（1.6）
        │
        ▼
用户照份额，自行手动下单
```

## 1.8 看板报的两个数字，口径不同，不许混用

看板上有两个都跟"钱"有关的数字，它们回答的是**两个不同的业务问题**，所以取数规则必须分开：

| | 回答的问题 | 要什么样的净值 |
| --- | --- | --- |
| **市值口径** | 我这些持仓**现在值多少钱** | **最新拿得到的**那一份，哪天的都算数 |
| **收益口径** | 我**今天**赚了多少 | **必须是今天的数据**；今天没有就说没有 |

**为什么必须分开**：净值当晚才发布，所以盘中官方净值永远停在昨天。
- 若市值口径也要求"今天的数据"，盘中持仓总额会直接归零——用户明明有持仓，看板却显示 0。
- 若收益口径接受"最新可得"，那么盘中估算一断供，看板就会把**上一个交易日的涨跌**当成今天的收益报出来。**这不是显示滞后，是报了一个假数字。** 这件事真实发生过一次。

**非交易日例外**：周末和节假日今天本就不该有数据，此时收益口径回退到"最近可得"，
并且顶部标题相应地叫**「最新收益」**而不是「今日收益」——名字要跟着口径走，不能嘴上说今天、心里算上周五。

**收益金额的唯一公式**：

```
单只收益 = 持有份额 ×（活动净值 − 基准官方净值）
```

活动净值盘中取基准代理净值，官方披露后取当日官方净值；基准官方净值来自 KV 中与活动净值相邻的上一官方净值日。
百分比只回答“涨跌幅是多少”，由两次净值实时派生；它不是金额计算输入，绝不用于反推基准净值。
新增基金还没有两次官方净值时，收益显示为 `-`，不能用四舍五入百分比倒推出一个近似金额。

**「已更新」这个状态标记单独一套判据，比数值更严格。**
数值可以退让（拿不到今天的就用最近的，滞后但不错）；**状态不许退让**——
标记的语义是"今天的数据到了"，只要今天真数据没到，它就必须是灭的。
用昨天的数据点亮"已更新"，比显示空白更危险。**估算源失效时用基准推出来的代理值也不算"到了"**，
因为一条真数据都没到。

## 1.9 估值源断供时怎么办：基准代理

**业务节奏**：官方净值**每晚 19:00–23:00 陆续发布**，而那个时段用户基本不会开着看板。
这条节奏就是"为什么需要一个夜里替用户盯着、谁先发布就先记下来"的全部理由——
靠用户自己开着页面轮询，等于假设有人守着。

**盘中的空档**：公开第三方“基金实时估值”接口已不再作为可靠数据源。具体停供原因不作推断，
系统也不等待其恢复。没有真实估算时，「今天赚了多少」只能退化为方向代理。

**解法——基准代理**：用户对每只产品本来就有**自定义业绩基准**（季度审计习惯的产物）。
把"基准权重 × 实时指数涨跌"当作该产品的日内方向代理，填进估算位。这不是真净值，
只是让盘中方向可观察。当前产品设计不再依赖外部基金估值接口；若将来重新引入真实估值，
必须作为新的数据源变更单独验收，不能静默替换代理口径。

**代理的基准必须取最近官方净值。**
盘中官方最新值通常是上一官方净值日，直接作为代理基准；当晚正式净值落地后，若仍要展示代理列，
代理基准改用 KV 给出的前一官方净值日。这个基准必须直接来自官方净值记录，不能用官方百分比反推。
**按数据日期判，不按当前时钟判**，才能同时覆盖盘中、夜间落地、次日盘前、节假日回退这四种情况。

**权重表须随季报手工校核**——它是业务输入，不是技术参数。

**2026Q2 校核后的业务口径**：本轮目标是让盘中方向明显优于旧的宽基/国债占位，
不做历史回测，也不把代理包装成精确净值。ETF 联接基金跟踪其目标 ETF；
固收产品按季报拆成信用债、转债和权益风格腿；现金、回购等低波动资产按零涨跌处理。
兴全稳泰的主体是金融债与企业债，国债和转债接近零，因此从国债指数改为企债指数。
具体主模型、完整降级模型及隐藏行情代码以 `03-实现约束.md` 第 3.3 节为正式说明，
`js/config.js` 的 `BENCHMARK_PROXY` 为运行时唯一参数源。

## 1.10 多端同步：为什么要版本号

**使用场景决定设计**：用户在 PC / iOS 多端看盘，iOS 常被系统杀后台、多为冷启动。
用户配置分成两类，采用不同同步策略：

- **PE 档位配置**（`bucketStr`，如 `65,70`）：用户改动后立即推送 `fm_pe.json`，他端打开即拉取。
  它只是当前纪律档位，不是夜间 PE 数据锚；夜间锚由自动任务写 `fm_pe_engine.json`。
- **带版本配置**（基金列表、持仓、降权预案、优先卖出）：一旦被旧端覆盖，损失较大。
  因此遵循「**谁新谁赢 + 反向自愈**」：本地改动自增版本；拉取时只采纳更高的云端版本；
  若本地版本更高，下次拉取会把本地配置推回云端。

**业务含义**：用户任何一次有效编辑最终都不会被旧数据覆盖回退；且用户清空日志文件不影响同步（版本号写在配置自身，不依赖日志）。技术实现见 2.5。
